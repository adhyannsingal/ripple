# What Ripple does today

Ripple is a local Rust CLI in development for explainable TypeScript change impact. M0 source/graph/index contracts, M1 source understanding and the M2 cold persistent graph pipeline are implemented. M3 adds a pinned evaluation-only compiler oracle, comparison metrics and regression evidence. M4-T01 adds an immutable Git endpoint/tree/hunk library adapter. M4-T02 adds pure base/head symbol change classification with explicit file-level fallback and uncertainty. M4-T03 adds independent historical snapshots and revision-labelled impact union. M4-T04 exposes this through the diff CLI with versioned JSON and depth/display/hub summaries. M5 now adds default verified incremental index refresh, explicit full rebuild and guarded importer/reference reuse. The dedicated test command, expanded real-history correctness and performance/safety remain later tasks.

| Area | Implemented behavior |
|---|---|
| Capture | Supported TS/TSX, repository ignores, finite local config inheritance, package policy and recognized root lockfiles; anchored reads, explicit exclusions/symlink rules and content/path verification. |
| Syntax | Bounded Tree-sitter parsing, source spans, stable supported symbols, signature/body fingerprints, import/export/scope/reference facts and explicit unsupported diagnostics. |
| Semantics | Configured source lookup, aliases, named/star/default re-export fixed points and supported lexical local/imported calls/reads; shadowing, type-only and ambiguity stay explicit. |
| Storage | Schema-v2 immutable typed SQLite generations with atomic analysis/fingerprint caches, captured bytes/facts, atomic publication, integrity/version checks, concurrent reader/writer behavior and derived-summary recovery. |
| Git library | Pinned A..B commits, scanner-compatible raw trees, add/delete/rename/text hunks and explicit binary/mode diagnostics; no worktree/index mutation. CLI diff is implemented. |
| Change classification | Captured base/head facts and Git ranges yield added/deleted/body/signature/unchanged or uncertain symbol records; class/method boundaries, renames and global inputs stay explicit. Both endpoint graphs now feed revision-labelled impact; CLI diff exposes the full result. |
| Incremental | Digest/version-bound parse reuse, missing-probe/export dependency closure, guarded module/reference reuse, full fallback, retries and truthful counters; generated cold-equality guard. |
| Queries | Deterministic reverse witnesses with confidence/provenance, independent symbol-backed/module-fallback tracks, potentially-related test partitions, depth/display limits and hubs. |
| CLI | index, inspect, status, impact and diff in human/versioned JSON. Persistent queries verify freshness and reject stale/incompatible state; ambiguous symbols need qualified choices. |
| Verification | Fixture/adversarial tests, installed capability smoke, pinned TypeScript oracle/metric tests and Linux/macOS/Windows CI; see milestone reports for actual gate outcomes. |

From a supported Git project root, `ripple index .` builds or refreshes a verified generation (`--full` forces cold work); `ripple status` verifies it and `ripple impact path/to/file.ts::symbol` explains potentially affected code/tests. `inspect` remains a syntax-only debugging view. Use `--format json` for typed complete evidence. No Node runtime, database server, hosted service or project-script execution is required.

The installed v0.2 capability gate is `python3 scripts/m5-smoke.py --install-root /path/to/install`; it includes prior capabilities plus deletion/base/head/read-only evidence. The [pinned upstream diff demo](examples/m4-diff/README.md) retains explicit incompleteness. The reproducible repository demo is `python3 scripts/m2-smoke.py --binary target/debug/ripple`, after a locked workspace build; the installed form takes `--install-root`. It uses a disposable Git root with spaces/Unicode, checks a two-hop semantic witness and distinguishes one exact test from one conservative fallback addition. It also verifies stale-content rejection and unchanged Git-index bytes.

Index defaults to verified incremental refresh; `--full` cold-recomputes. Worktree verification reads/hashes contents and is not an OS-atomic snapshot. Supported package/module policy is narrow and diagnosed; external Git filters, submodules and nested Git projects are unsupported. Test sets are potentially related, never sufficient. The oracle measures only the documented 3-edge mini and 16-edge external source projection. Generated cold equality is established only within the documented 120-comparison and targeted fixture bounds; expanded properties/replay are M6. General accuracy, latency and mutation-safety are not established.
