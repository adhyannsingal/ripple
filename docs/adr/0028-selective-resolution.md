# ADR 0028 — Guarded module cutoff and reference reuse

Status: accepted for M5-T03

Retain verified capture, parser reuse, atomic publication and complete canonical comparison. The graph policy token becomes `ripple-graph-v2-reuse`, so older analyzer caches require a reported full refresh. Previous analysis must come from a compatible validated/sealed generation; it is not an authenticated proof from an untrusted producer.

Reuse module analysis for identical resolver inputs, or a narrow stable-coordinate body case: same inventory/config/policy, clean diagnostic-free supported facts, complete previous module context and all signature hashes available. Compare every fact after removing only references and symbol body hashes, normalizing symbol collection order. Keep declaration/signature/body spans, exports/imports/root scopes, signature hashes and diagnostics. These are the actual inputs used by the module resolver; references/body hashes do not drive module exports. Coordinate changes, signature/shape changes, new/deleted paths or unknown contexts fall back to the existing complete bounded module/re-export fixed point. Missing hashes alone never establish unchanged external facts.

Watch old and new lookup winners plus missing probes and import/re-export dependencies. Propagate changed facts, candidate records and external-surface changes through a deterministic cycle-safe closure. A reference file can be reused only with identical complete facts and imported bindings/config, and no prior candidate semantic edge. When reached by invalidation, its external surface must additionally be known and unchanged. This uses fingerprints as a gate, not as a substitute for evidence/input equality. Imported binding equality retains origins/type flags/declaration/witness locations. Newly satisfied misses, removed exports, ambiguous/cyclic forwarding and moved origins are consequently re-resolved. Candidate semantic references are always reconsidered; no new candidate inference is introduced.

Rebuild current file/symbol/definition nodes. Reuse only eligible CALLS/REFERENCES and their reference-level unknown boundary records. Always reconstruct module edges/unknowns from current module analysis, including deterministic global module ordinals; do not carry old module-boundary IDs across additions/deletions. Validate the assembled typed graph before publication. Resolver/config/discovery uncertainty and both impact evidence tracks remain unchanged.

Counters report accepted-attempt module/reference files actually resolved/reused, module-cache reuse, invalidation candidates and unchanged external surfaces. The stable body fixture performs one parse, zero module resolutions and one reference-file resolution, preserving both importer files. This does not establish end-to-end speed: verification, validation, graph reconstruction and generation writes still process broad state. Performance is not measured; no benchmark harness exists yet.

The 96-comparison basic guard is extended first on the conservative updater with 24 fully resolved body comparisons, then rerun after optimization. The matrix additionally covers coordinate fallback, signature/export/class/alias changes, renamed/deleted/missing targets, cyclic/ambiguous barrels, candidate cleanup and unknown preservation. Fresh mini/external oracle baselines remain 3/3 and 16/16 in their documented projections. CLI incremental defaults remain T04; broader adversarial/replay and performance evidence are M6/M8.
