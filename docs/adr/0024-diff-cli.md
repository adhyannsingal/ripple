# ADR 0024 — Diff CLI output and v0.2 capability gate

Status: accepted

`ripple diff A..B --root ROOT` composes the Git adapter, independent historical cold snapshots and revision-impact library. Resolve endpoint refs once to explicit commits; `A...B`, missing endpoints and non-commit objects fail with actionable errors. The command needs Git objects, not a persistent index or clean worktree, and never checks out, stages, fetches or publishes local index state. Operational errors produce no success document.

Use the existing format-v1 envelope with `command: diff`. Data retains requested comparison and resolved endpoints, analyzer/hash/schema versions, endpoint config hashes, all Git diagnostics, classified/changed-symbol counts and the complete typed `RevisionImpact`. Omit wall-clock/generation metadata so identical endpoint queries produce identical bytes. Preserve all endpoint uncertainty, unindexed changes, depth frontiers and both witness evidence tracks/revisions. Unknown/non-text Git records make the envelope incomplete even if the supported graph is empty.

Human output uses terminal-safe escaping, reports classification/file reasons, test evidence partitions and actual head presence, visited counts, nodes by depth and high-fan-out nodes. Depth counts graph hops; module fallback from symbols includes the initial defining-file bridge. The reporting threshold remains 50 distinct direct dependents in the applicable track; hubs never prune. `--depth` defaults to unlimited and marks real frontier truncation incomplete. `--limit` defaults to 100 and limits rows per human section, reporting omissions; it does not alter full JSON classifications, rows, witnesses or selected tests. The full selected sets, active/absent/present-unindexed partitions and indexed-head denominator remain explicit in JSON. Unresolved context is graph-wide, not proven reachable. No selected test set is sufficient.

The workspace becomes `0.2.0-dev`, a capability candidate, with no public release/tag or new schema introduced. Existing persistent analyzer/hash/schema compatibility remains authoritative. The CI install gate now runs `scripts/m4-smoke.py`, which includes prior M2 capability checks and adds real base/head/deletion/limit/read-only assertions on Linux, macOS and Windows. Dedicated test CLI, incremental updates, mutation safety and benchmarks remain later tasks. The pinned full upstream history example deliberately retains unsupported policy/syntax and incompleteness; it is not the narrower M3 oracle measurement.
