# Current limitations

Ripple currently has core contracts, repository discovery, TS/TSX syntax parsing and supported symbol/fingerprint extraction; `inspect` exposes them with human/JSON output; index/status/impact now expose supported dependency analysis; Git diff/test commands and incremental updates remain upcoming. No resolver accuracy, complete graph, incremental correctness or test sufficiency is claimed.

Discovery uses one explicit project root, `.ts`/`.tsx`, repository `.gitignore`/`.ignore`, mandatory excludes and fixed test basename suffixes. It does not inherit parent/global Git ignores or `.git/info/exclude`. It skips all symlinks with diagnostics, rejects nonportable/case-colliding paths, and requires UTF-8 source and ignore text. Selected inputs are limited to 16 MiB, nesting to 128 and visited entries to 100000; directory enumeration enforces its remaining budget while iterating. The scanner retains inputs; integrated config/package policy is described below. See [ADR 0011](adr/0011-source-discovery.md).

Worktree reads are anchored to an open directory handle and validate regular opened files; replacing the root pathname cannot redirect capture. Capture is still not atomic under concurrent content changes, and aggregate source memory is not capped independently of file/entry limits. Initial root selection, hard links and mount changes are outside the containment guarantee. M2-T05 now verifies source/config/ignore manifests with bounded retries before publication. The immutable Git tree provider remains M4 work. No performance benchmark has been run.

Parsing uses pinned Tree-sitter grammars with a 16 MiB input cap, a five-second progress-callback budget and at most 1024 detailed recovery diagnostics. Recovered trees retain explicit errors; cancellation publishes no syntax facts. Tree-sitter syntax does not establish TypeScript semantics. Invalid UTF-8 and unsupported source extensions fail without lossy conversion.

Symbol extraction supports top-level functions, const-bound arrow/function expressions, classes and methods. It does not create separate symbols for nested callbacks/functions, class fields, static initializers or const-bound class expressions. Ambient-only/duplicate implementation groups, non-const function bindings, numeric/computed/escaped names and unsupported type/namespace forms are diagnosed. Function/class literals behind `as`, `satisfies`, angle-bracket type assertions or postfix non-null assertions remain unsupported binding targets and emit diagnostics. Direct exports and local export aliases of these bindings withhold complete file signature fingerprints; body evidence for supported declarations remains available. Overload support requires consecutive signatures followed by one implementation. Simple named/default/local export syntax supplies exposure metadata. The complete extraction API now supplies supported imports, exports, lexical scopes and runtime references, as described below.

Structural hashes preserve supported syntax/meaningful lexical text and restricted line breaks, including the pinned grammar's comment/ASI limitation. They do not infer TypeScript return types or prove semantic API equivalence. Conservative downstream invalidation is required for inferred/aliased/imported types and unsupported constructs. Recovered files, CommonJS/namespace or other unmodeled export forms/spellings and directive-like comments withhold complete signature hashes. Decorator runtime effects are not modeled. Unrepresented class member bodies remain in class fingerprints; represented method bodies have separate hashes. Node traversal is capped at 1000000, with diagnostic truncation explicit. See [ADR 0012](adr/0012-syntax-hashes.md). No early-cutoff optimization or performance measurement is claimed.

Import/export extraction supports unescaped string module specifiers and identifier names; it captures nonrelative specifiers without resolving them. Binding-level type-only imports and named re-exports remain distinct from runtime calls. Namespace imports are recorded with diagnostics; namespace/empty re-exports, import-equals, escaped strings/names, import attributes and arbitrary default export targets remain unsupported or partial. The pinned grammar recovers on `export type *`; named type-only re-exports work. Empty type-only imports are diagnosed and omitted instead of becoming runtime side-effect facts.

References are syntax evidence, not resolved edges. Direct identifier calls and runtime value uses retain ownership and lexical bindings, including destructuring, parameter/block shadowing, body var hoisting and module-level test callbacks. Receiver/computed/optional/constructor/asserted/eval/require calls and all dynamic imports are explicitly unsupported for precise resolution. Ambient/namespace and with bodies are skipped with diagnostics. No flow-sensitive assignment, TDZ execution, dynamic scope, decorator behavior or complete JSX/TypeScript semantics is modeled; JSX component identifiers provide value-use evidence only. A resolver must preserve these uncertainty boundaries rather than trusting name matches.

Supplemental extraction is limited to named-tree depth 256, 8192 scopes, 100000 references and 8 MiB aggregate reference text; limits withhold imports/exports/scopes/references together while retaining valid symbol facts and an explicit diagnostic. This bounds supplemental output; it is not an independent total-process memory guarantee. Failed parsing emits no facts; recovered statements do not publish complete import/export/call records. See [ADR 0013](adr/0013-reference-extraction.md). No resolver accuracy or performance measurements exist yet.

Inspection currently captures the entire explicit root before selecting a file. Other invalid/oversized discovered source/config/ignore inputs can fail it, and discovery diagnostics from another path can mark the report incomplete. It uses captured bytes without publishing an index, verifying manifest freshness or guaranteeing an atomic filesystem snapshot. See [CLI usage](cli.md). Diff/test remain explicit placeholders; index/status/impact are implemented.

M2-T01 is an initial captured-source matching/direct-binding library. Its relative/direct-binding path matches do not certify Node/TypeScript module modes; package entries/conditions and directory manifests remain unimplemented. M2-T06 now supplies effective config and conditional alias lookup through separate APIs. Nonrelative specifiers remain unresolved in the legacy M2-T01 API; the configured API supports the documented local aliases. Re-export chains are available through the new M2-T07 configured API; calls remain deferred. Lookup candidates and source uncertainty are retained, but no graph/index/impact feature is enabled by these records alone. See [resolution scope](resolution.md).

The M2-T03 [storage library](storage.md) persists caller-supplied validated snapshots and verifies all captured byte digests. Storage alone does not capture/re-observe live files or certify analyzer semantics; M2-T05 composes it with index/status commands. Schema v1 rejects incompatible versions rather than upgrading them. Archived generations have no garbage collection yet. Storage requires a private local directory: observed symlinks/nonregular files are rejected, but hostile concurrent path replacement, hard links, network filesystems and power-loss fault injection are outside tested guarantees. Generation seals detect accidental corruption, not malicious rewriting. Resource caps are explicit; performance is not measured.

M2-T04 adds the [reverse-query library](graph-model.md#query-library-m2-t04), with impact CLI composition now implemented in M2-T05. It operates on supplied validated graphs and caller-labelled revisions; it does not verify input freshness, resolver accuracy or Git origins. Test sets use existing file classification and remain potentially related. Depth limits can omit downstream results and are explicit; display limits do not affect traversal or selection. Unresolved records are graph-wide context, not proven reachable dependencies. Complete witness output can be large; performance and resource quotas are not measured. Revision-aware active/deleted-test selection remains M7 work.

M2-T06 configuration is evaluated from supplied bytes only. The cold builder extends scanner capture with recursive local inheritance/package/lock inputs and freshness checks. M2-T07 composes configured lookup into a new binding/re-export API; legacy resolve remains relative/direct-only and CLI composition is implemented in M2-T05. Only one local extends chain and the [documented source/config policy](resolution.md) are supported. Package/array extends, configDir macros, files/include/exclude scope, project references, modern unsupported module modes and unknown resolution options produce diagnostics and block successful configured matches. Checking/emit options are not TypeScript validity proof. Equal-priority wildcard patterns remain ambiguous. Legacy baseUrl semantics are explicit; TypeScript 6+ equivalence is not claimed. Config fingerprints deliberately change on raw comment/format/overridden-input changes. No compiler-oracle accuracy or performance measurement exists.

M2-T07 resolves a bounded supported export subset to original declarations; M2-T02 adds call graphs and M2-T05 enables index/status/impact. Named/star/default and unique imported-alias forwarding are supported; namespace forwarding and unsupported/incomplete export forms stay unresolved. Type-only flags remain separate from runtime eligibility. Unknown star surfaces and empty cyclic branches can conservatively block bindings. Artifacts are serializable persistence handoffs; their validator recomputes against captured inputs, while index/incremental tasks own SQLite/cache composition and freshness. External fingerprints omit bodies/locations and do not prove semantic API equality or safe cutoff. See [resolution policy](resolution.md#configured-bindings-and-re-exports-m2-t07) for bounds and unsupported cases.

M2-T02 supports direct lexical identifier calls/value reads and configured imported origins. Flow-sensitive reassignment, TDZ execution, receivers/method dispatch, constructors, optional/computed calls, dynamic imports and full Unicode identifier normalization are not resolved; they remain explicit boundaries. No candidate-producing inference is claimed. Captured supported graph construction is separate from live input verification and CLI wiring.

M2 cold commands require one Git repository root, reject submodules/nested Git projects and repository external clean/process filters, and use isolated repository-local Git settings. No checkout/stash/stage/network operation or project-script execution is requested. Active hostile filesystem/Git-metadata races, malicious Git binaries, hard links and network filesystems are outside the private-local-root guarantee. Reads are content-verified captured views, not OS-atomic snapshots; edits after verification make them stale. Package entry/modern mode policy is deliberately narrow and diagnosed. Accepted capture is capped at 16 MiB/input and 256 MiB total; this is not a total-process memory or end-to-end latency guarantee. Query verification performs full captures/hashing and module completeness reconstruction; no performance measurement is claimed. Module/metadata sidecars are derived and may remain pending after a committed DB generation. Incompatible schema repair is explicit; no automatic destructive cache deletion occurs.

## Resolver oracle baseline (M3)

The pinned TypeScript 6.0.3 compiler API compares a fixed ES2022/CommonJS/Node10 source projection under oracle policy v1. It deliberately excludes receiver/computed/optional/constructor dispatch, nested callback owners, external/variable targets and non-runtime syntax. The four-source sourcemap-codec sample has 16 eligible semantic pairs; 16/16 precision/recall does not establish full-project or general TypeScript accuracy. Raw reports retain 567 unresolved occurrences, 524 oracle excluded occurrences, one unsupported constructor definition and six out-of-scope constructor-related reads. No supported mismatch was observed, so M3-T03 adds a composition regression rather than claiming a resolver fix. See [evaluation](evaluation.md) and its raw reports. No dedicated test-safety, incremental or performance conclusion follows.

## Immutable Git adapter (M4-T01)

The library pins explicit A..B endpoints and exposes raw trees/file changes/hunks. The CLI diff command is still pending M4-T04. Historical trees share scanner policy through the core SourceTree interface. UTF-8 portable paths only; symlinks are visible/excluded, submodules fail explicitly, and binary/non-UTF-8 or nonregular changes retain file-level diagnostics without invented text hunks. Limits: 100000 tree entries, 8 MiB per Git command/input blob, 256 MiB repeated blob reads per endpoint and a 10-second per-command deadline. These are not total-process resource guarantees. Git must support `--no-lazy-fetch`; missing/pruned objects fail and no network fetch is requested. Rename hints use a bounded Git heuristic and do not guarantee stable symbol identity. The trusted Git binary/private-metadata assumptions remain.
