# Ripple thesis and owner explanation

Ripple investigates whether a local, bounded static-analysis engine can turn TypeScript Git diffs into explainable downstream impact while keeping uncertainty visible. Its engineering contribution is the composition of symbol identity, structured change classification, two-revision dependency evidence, verified incremental reuse and reproducible evaluation. It does not claim to invent change impact or regression-test selection; [prior art](prior-art.md) places the work in context.

The pipeline is: capture supported source/config/ignore bytes; extract syntax facts; resolve supported bindings into a graph; map immutable Git endpoints to changed symbols/files; reverse-traverse independent semantic and import-fallback tracks; report witnesses, uncertainty and potentially related tests. A resolved import is evidence of a module relationship, not proof that a particular exported symbol is relevant. Both base and head graphs preserve deleted or removed relationships.

Stable semantic IDs omit line numbers and revisions. Structured versioned hashes retain syntax and meaningful text, including automatic semicolon insertion. Persistent generations are atomic, captured inputs are reverified before publication, and stale queries fail rather than silently refresh. Conservative fallback is preferable to unsupported certainty. [Architecture](architecture.md) and [ADRs](adr/0001-rust-core.md) give the concrete contracts.

The evaluation separates questions: the compiler oracle measures agreement only in a declared supported projection; canonical cold/incremental equality checks state consistency; replay adds finite real-history cases; controlled runtime mutations measure selected failing files; workflow benchmarks measure explicit costs. None alone proves complete TypeScript semantics or safe test omission. The current designed mutation campaign has known dynamic/global-state misses and combined selection equals static file-import selection. Performance profiling shows verified input/provenance work dominates the small supported workload, so an unsafe metadata shortcut was rejected. [Evaluation](evaluation.md) and [benchmarks](benchmarks.md) retain denominators and raw evidence.

The owner should be able to explain why evidence kind differs from confidence, why base/head both matter, why missing lookups invalidate caches when files appear, why no-op indexing still writes a generation, and why a small selected ratio is not a safety result. Read [graph model](graph-model.md), [resolution](resolution.md), [incremental](incremental.md) and [limitations](limitations.md) with those questions in mind.
